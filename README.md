# End-to-End MLOps Pipeline — Student Academic Risk Prediction

Implementation of the GeeksforGeeks tutorial *["End to End MLOps Pipeline: A Comprehensive Project"](https://www.geeksforgeeks.org/machine-learning/end-to-end-mlops-pipeline-a-comprehensive-project/)*,
organized as a runnable project instead of a single notebook.

Predicts whether a student will **Dropout**, stay **Enrolled**, or **Graduate**, based on
enrollment and academic performance data.

## Why these files exist (the website only shows code snippets/one notebook)

The tutorial's code is all written as one long notebook meant to be read top-to-bottom.
A real pipeline needs it split up, because each stage runs in a different context:

| File | Type | Why this type |
|---|---|---|
| `notebooks/eda_and_training.ipynb` | Notebook | For you to explore data and prototype interactively, cell by cell — matches the tutorial exactly. |
| `src/train.py` | Python script | Same training logic, but runnable **headlessly** (`python src/train.py`) — required because CI/CD (GitHub Actions) and Docker can't click through notebook cells. |
| `src/app.py` | Python script | FastAPI needs to run as a long-lived server process (`uvicorn`), which only works as a `.py` module, not a notebook. |
| `model.pkl`, `scaler.pkl`, `label_encoder.pkl`, `feature_columns.pkl` | Binary artifacts | **Not hand-written** — produced automatically by `train.py` (via `joblib.dump`). They are the serialized trained model/preprocessors used at inference time. |
| `Dockerfile` | Container build | Packages `app.py` + artifacts into a portable image. |
| `.github/workflows/cicd.yml` | GitHub Actions | Automates: install deps → train → report metrics (CML) → build/run Docker image, on every push. |

No PyTorch is used — this is a tabular classification problem, so scikit-learn's
`RandomForestClassifier` is the right tool (PyTorch is for deep learning on
unstructured data like images/text/audio).

## Step-by-step: run it locally

### 1. Create a virtual environment and install dependencies

```bash
cd end-to-end-mlops-demo
python3 -m venv .venvmlopsend2enddemo
source .venvmlopsend2enddemo/bin/activate
pip install -r requirements.txt
```

### 2. Explore the data (optional, interactive)

Open `notebooks/eda_and_training.ipynb` in VS Code / Jupyter and run the cells top to
bottom. This mirrors the article: load data → explore → preprocess → train → tune →
evaluate → save artifacts.

### 3. Train the model (headless, what CI/CD actually runs)

```bash
python src/train.py
```

This will:
1. Load `data/data.csv`.
2. Preprocess (drop irrelevant columns, one-hot encode `Course`, scale features, encode target).
3. Split into train/test and balance classes with SMOTE.
4. Run `GridSearchCV` over a Random Forest hyperparameter grid.
5. Log parameters/metrics/model to MLflow (local tracking store in `mlruns/`).
6. Evaluate on the held-out test set and print accuracy + classification report.
7. Save a confusion matrix plot to `plots/results.png` and a `report.md` summary.
8. Serialize `model.pkl`, `scaler.pkl`, `label_encoder.pkl`, `feature_columns.pkl` to the project root.

### 4. (Optional) Inspect experiment tracking with MLflow

```bash
mlflow ui
```

Open http://127.0.0.1:5000 to compare runs, parameters, and metrics.

### 5. Serve predictions with FastAPI

```bash
uvicorn src.app:app --reload --host 0.0.0.0 --port 8000
```

Open http://127.0.0.1:8000 for a simple HTML form, or http://127.0.0.1:8000/docs for
the interactive Swagger UI. Example request:

```bash
curl -X POST http://127.0.0.1:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"Marital status":1,"Application mode":17,"Application order":5,"Course":171,
       "Daytime/evening attendance":1,"Previous qualification":1,
       "Previous qualification (grade)":122,"Nacionality":1,
       "Mother'"'"'s qualification":19,"Father'"'"'s qualification":12,
       "Mother'"'"'s occupation":5,"Father'"'"'s occupation":9,
       "Admission grade":127.3,"Displaced":1,"Educational special needs":0,
       "Debtor":0,"Tuition fees up to date":1,"Gender":1,"Scholarship holder":0,
       "Age at enrollment":20,"International":0}'
```

### 6. Containerize with Docker

```bash
docker build -t academic-success-predictor .
docker run -p 8000:8000 academic-success-predictor
```

Visit http://localhost:8000 — same app, now running in a container.

### 7. CI/CD (GitHub Actions)

`.github/workflows/cicd.yml` runs automatically on every push to `main`:
1. Checks out the repo and installs dependencies.
2. Runs `python src/train.py` to retrain and regenerate `report.md` / `plots/results.png`.
3. Posts the metrics report as a PR/commit comment via [CML](https://cml.dev).
4. Builds the Docker image and runs it as a smoke test.

## Notes

- `model.pkl` and the other `.pkl` artifacts are **gitignored** — they're build outputs,
  regenerated by `train.py` (locally or in CI), not something you edit or commit.
- If you re-run training, accuracy will vary slightly run to run due to SMOTE/GridSearchCV
  randomness unless you fix all random seeds (already set to `random_state=42` where sklearn
  supports it).
